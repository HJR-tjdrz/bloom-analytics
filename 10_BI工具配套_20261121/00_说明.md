## 二、数据源：两条路可选

### 路线 A：直连 MySQL（推荐，数据实时）

| 参数 | 值 |
| --- | --- |
| 主机 | `127.0.0.1` |
| 端口 | `3306` |
| 数据库 | `bloom_dw` |
| 账号 | `.env` 里的 `bloom_app`（只读权限即可，当前是 ALL，生产环境建议建只读账号） |
| 推荐表 | `ads_kpi_monthly`、`ads_customer_rfm`、`ads_product_performance`、`ads_channel_efficiency`、`ads_promo_roi`、`ads_inventory_analysis`、`ads_forecast`、`fact_sales`、`dim_*` |

> Tableau 需要 MySQL 8 驱动（`mysql-connector-odbc` 或 Tableau 自带驱动）；
> Power BI 用 MySQL connector（需要装 `MySQL Connector/NET`）。

## 三、三个工具的定位（怎么选）

| 工具 | 优势 | 本项目的用法 |
| --- | --- | --- |
| **Tableau** | 拖拽快、仪表板美观、适合业务自助 | 用 CSV/MySQL 做 4 张工作表 + 1 个仪表板，见 `01_Tableau操作手册.md` |
| **Power BI** | 与 Excel/Office 生态结合好、DAX 强大、企业部署便宜 | 星型模型 + 20 个 DAX 度量值，见 `02/03` |
| **R** | 统计与可视化可编程、可复现、适合做批量报告 | ggplot2 出 4 张出版级图，见 `04_R可视化脚本.R` |

> 面试时如果被问"为什么不只用 Tableau"：
> 因为**看板要能嵌入业务系统**（自建 Web）、**BI 要能自助分析**（Tableau/Power BI）、
> **分析要能复现**（Python/R 脚本）。三者不是替代关系，而是不同场景的最优解。

## 四、验证方式

1. 打开 `data/ads_kpi_monthly.csv`，35 行，最后一月 2026-11；
2. Tableau 连接 `data/` 目录（或用文本文件连接器逐个添加）；
3. Power BI「获取数据 → 文本/CSV」→ 选 `data` 下文件 → 按 `02` 的说明建关系；
4. R 脚本：`source("04_R可视化脚本.R")`，图片输出到同目录 `r_output/`。

> 三个工具的图表**应当与 Web 看板数字一致**（都来自同一批 ADS 表）。
> 如果对不上，优先怀疑筛选条件（例如 Tableau 默认会把"已取消"算进去），
> 而不是数据本身——这也是"口径统一"重要性的现实案例。
