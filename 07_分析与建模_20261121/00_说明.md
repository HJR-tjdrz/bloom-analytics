## 三、方法论上的三个坚持

### 3.1 口径写清楚，边界说明白

每个报告开头都会写"这个数怎么算的"，并且在给不出结论的地方**明确说给不出**：

- 促销章节：「**不提供"活动增量 ROI"**」——因为活动与节日高度共线，没有对照组，
  观测数据无法识别因果；只给"让利效率"（活动毛利 / 让利金额）。
- BCG 章节：真正的波士顿矩阵需要"相对竞争对手份额"，
  本项目用"品类内相对份额（本商品 / 品类第一）"代理，并明确标注。
- 关联规则章节：提升度只说明**相关性**，不说明因果，验证需要 A/B 实验。

> 面试时最容易被追问的就是"你这个结论可靠吗"。
> 提前把边界讲清楚，比给出一个漂亮但站不住的结论更专业。

### 3.2 每个结论都能下钻到明细

报告里每个数字都对应一段确定性 SQL（在 `bloom/analysis/*.py` 里），
任何一行数据都能用一条 SQL 捞出来。例如：

```sql
-- 验证"重要价值客户占 15.1% 但贡献 31.7%"
SELECT rfm_segment, COUNT(*) AS customers,
       SUM(monetary) AS gmv,
       SUM(monetary) / (SELECT SUM(monetary) FROM bloom_dw.ads_customer_rfm) AS share
FROM bloom_dw.ads_customer_rfm GROUP BY rfm_segment;
```

### 3.3 结果落库，而不是只存在报告里

5 张结果表让第 4 轮的看板可以**直接查表出图**，
不必在接口里重跑一遍复杂计算；也便于做"今天 vs 上周"的分群漂移监控。

## 四、怎么跑

```bash
python run.py analysis        # 或在 Windows 双击 90_run_analysis.bat
```

- 约 **15 秒**跑完 8 个模块（预测模块含模型拟合，占一半时间）；
- 前置条件：第 1 轮（数仓）+ 第 2 轮（特征表）已跑完；
- 全流程幂等：重跑会覆盖报告与结果表，不会重复累加。
