## 三、发布到 GitHub / Zenodo

详见 **[`05_发布与归档指南.md`](05_发布与归档指南.md)**，这里只放结论：

### 3.1 不装 Git 也能上传

| 方式 | 需要装什么 | 结论 |
| --- | --- | --- |
| **GitHub Desktop** | 桌面客户端 | ✅ **推荐**，自动遵守 `.gitignore`，182 个文件一次搞定 |
| **网页拖拽上传** | 不用装 | ⚠️ 可行，但**不读 .gitignore**、单次 ≤100 文件，要按 3 批传且手动避开 `.env` / `.venv` / 数据 CSV |
| **命令行 git** | Git | 略麻烦 |

> 关键风险：**网页上传不会自动排除 `.env`**（里面是数据库密码）。
> 用 GitHub Desktop 就没有这个问题。

### 3.2 Zenodo 的正确姿势

不是"传个 zip 就完事"，而是：

```
GitHub 仓库（公开）
   → Zenodo 设置里授权 GitHub
   → 把仓库开关拨到 ON（必须在发 Release 之前）
   → 在 GitHub 创建 Release（tag v1.0.0）
   → Zenodo 自动归档 + 生成 DOI（约 1~2 分钟）
   → README 加 DOI 徽章
```

细节（含两个 DOI 的区别、常见坑）见 `05_发布与归档指南.md` 第六节。

### 3.3 上传前要改的 3 处占位符

| 文件 | 改什么 |
| --- | --- |
| `.zenodo.json` | `YOUR_NAME` / `YOUR_SCHOOL_OR_ORG` / `YOUR_GITHUB_USERNAME` |
| `CITATION.cff` | `YOUR_FAMILY_NAME` / `YOUR_GIVEN_NAME` / `YOUR_SCHOOL_OR_ORG` / ORCID（没有就删掉该行） |
| `README.md` | 引用段落里的 `YOUR_NAME` / `YOUR_GITHUB_USERNAME` |
